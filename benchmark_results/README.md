## 5.1_retrieval — `scripts/benchmark_retrieval.py`

Twenty queries (ten English, ten Welsh) over three retrieval configurations,
scored under a strict and a relaxed relevance rule. Three subfolders record the
same benchmark at three states of the retriever, which is what Table 5.2 in the
report reproduces:

| Folder | Retriever state | Overall hybrid MRR (relaxed) |
|---|---|---|
| `stage1_baseline/` | no exclusion filters | 0.53 |
| `stage2_glosses_excluded/` | BydTermCymru glosses out of the dense pass | 0.61 |
| `stage3_final_reported/` | conversational intents also excluded | **0.66** |

**`stage3_final_reported/` is the state reported in Table 5.1.** Stages 1 and 2
were regenerated by reverting the change and re-running; the benchmark is
deterministic and reproduced its original output cell for cell.

Each folder holds `retrieval_summary.csv` (aggregates), `retrieval_per_query.csv`
(rank of the gold document for every query and configuration) and
`retrieval.json`.

## 5.2_latency — `scripts/benchmark_latency.py`

Thirty requests per provider (15 English, 15 Welsh), timed around the full
`/api/chat` round trip against the local backend, so tunnel overhead is
excluded.

| File | Contents |
|---|---|
| `latency_per_query.csv` / `.json` | Claude Haiku 4.5, the deployed provider |
| `latency_ollama_per_query.csv` / `latency_ollama.json` | Llama 3.1 8B Q5_K_M local fallback |
| `latency_benchmark.xlsx` | both runs, live-formula summary, native Excel box plot |
| `figure_5_1_latency_boxplot.png` | Figure 5.1 |

Headline: Claude mean 2.81 s (N1 met); local fallback mean 6.05 s overall but
8.51 s for Welsh alone, exceeding the 8 s target.

## 5.3_language_detection — `scripts/benchmark_f2_endtoend.py`

**`f2_endtoend_per_query.csv` is the reported result.** One hundred queries sent
to the running system with no language declared; records the language detected,
the language the answer was actually written in (classified independently by
Lingua), the intent, sources shown and the reply text. 99/100 correct on both
measures.

| File | Contents |
|---|---|
| `langdetect_sample_TO_LABEL.csv` | the sample as drawn, before labelling |
| `langdetect_sample_labelled.csv` | ground truth, with the Lingua cross-check column |
| `f2_endtoend_per_query.csv` / `.json` | **end-to-end run — cite this one** |
| `langdetect_per_query.csv` / `langdetect.json` | component-level check of `detect_language()` only |

The component-level files are a faster unit check of the detector function in
isolation. They are not the evidence for F2, which is a claim about the system,
and should not be cited in the report.

Sample built by `scripts/make_langdetect_sample.py` (seed 42, reproducible).

## 5.4_source_attribution — `scripts/benchmark_sources.py`

The same 100 queries, recording every source the system displayed: 256 in
total.

| File | Contents |
|---|---|
| `sources_per_source.csv` | one row per displayed citation — title, URL, HTTP status, index-provenance check |
| `sources_per_query.csv` | one row per query — how many sources were shown |
| `sources_relevance_TO_RATE.csv` | **needs a human rating** — 20 queries, scale 2/1/0 |
| `sources.json` | full structured output |

Headline: 256/256 citations traced to a document in the index, 256/256 resolved
to a live `uwtsd.ac.uk` page, 96% of queries displayed at least one source.

## Reproducing

Retrieval and language detection need no running server. Latency, the F2
end-to-end run and source attribution all POST to a live backend, so start it
first:

```
python -m uvicorn app.main:app --port 3001
```

```
python scripts/benchmark_retrieval.py
python scripts/benchmark_latency.py                 # --tag ollama for the fallback run
python scripts/make_langdetect_sample.py            # writes the TO_LABEL sheet
python scripts/benchmark_f2_endtoend.py             # needs the labelled sheet
python scripts/benchmark_sources.py                 # needs the labelled sheet
```

`benchmark_f2_endtoend.py` classifies reply language with Lingua
(`pip install lingua-language-detector`); without it that column reads `?` and
the detection column is unaffected.
